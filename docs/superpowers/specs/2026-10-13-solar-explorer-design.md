# Solar：浏览器太阳系探索器设计

日期：2026-10-13

状态：第一版实现与生产回归已完成；目标 M5 实机、高精度独立基准以及长时观测超时原因仍有未覆盖项，详见 README。

## 1. 目标与约束

构建受 SpaceEngine 探索体验启发的浏览器太阳系漫游项目，优先保证真实尺度下的空间感、导航手感和天体近景，而不是科普面板的数量。

- 运行方式：本地开发服务器与静态网站部署，纯前端。
- 用户指定的主要设备：Mac mini，M5，16 GB 内存，Chrome。
- 第一版以桌面键鼠操作为准；手机、触屏和其他浏览器暂不作为验收平台。
- 界面语言：中文，支持中英文天体名称搜索。
- 技术路线：TypeScript、React、React Three Fiber / Three.js、Vite。
- 不引入账号、数据库、业务后端、在线星历服务或游戏引擎。
- 用户已授权按计划完成开发；后续 Git 初始化、提交和公开发布仍需单独明确授权。

## 3. 第一版范围

### 3.1 天体与视觉

- 太阳、八大行星、月球，共十个可选中的核心天体。
- 土星环是土星的视觉组成部分，不作为独立导航目标。
- 行星贴图、太阳光照、昼夜分界、自转和轴倾角。
- 地球大气边缘、云层、夜面城市光；太阳光晕。
- 背景星空只表达环境，不宣称是真实完整星表，不可飞向或选中。
- 第一版不做日月食预测和跨天体遮掩精度保证；复杂环影与高质量动态阴影留待性能评估。
- 视觉是面向观赏的近似渲染，不承诺物理测光精度；星空与曝光允许艺术化调整。

地表仅为球面纹理，不提供地形、着陆、步行或大气内飞行。最低观察高度先限制为目标半径的 1%，即相机到球心距离不小于半径的 1.01 倍。

### 3.2 导航

- 自由飞行：W/A/S/D 平移，Q/E 升降，右键拖动观察，滚轮调整速度档位。
- 环绕观察：左键拖动围绕天体旋转，滚轮改变观察距离；自由飞行和跟随模式保留右键转头。
- 列表与搜索：按中英文名称查找十个核心天体；单击列表或搜索结果后自动平滑飞近、居中并进入环绕。输入时禁用飞行快捷键。
- 场景内选中：左键单击天体或标签，仅更新选中目标，不自动改变相机模式。按下到抬起之间一旦移动超过 5 像素即视为拖动，即使回到起点也不触发选择。
- 飞向：单击列表/搜索结果、按钮或 G 键启动，默认约 3 秒；目标保持在画面中，终点按半径与视场角计算。
- 飞向在时间加速时持续更新目标终点；用户移动输入或 Escape 立即取消。
- 飞行路径避免穿过核心天体；使用路径检测或明确的绕行，不只检查终点。
- 跟随：保持相机相对天体中心的位置偏移，不默认随天体自转旋转。
- 返回全景：显示太阳系概览，真实尺度下主要依赖轨道与标签定位。
- 显示当前目标、距离、速度和导航状态；这些导航指标采用真实物理单位。
- 轨道使用与星空清晰区分的蓝灰色细线，不通过提高整体曝光来提亮。可切换标签、轨道与全部界面的显示状态；隐藏界面后保留恢复提示或可发现的快捷键。

浏览器不需要自动申请指针锁定；右键拖动仅在画布内阻止上下文菜单。失焦或切换标签页后清空按键状态，防止相机继续移动。

### 3.3 时间

- 默认从当前时间开始，以 1 倍速运行。
- 时间面板支持暂停、正向与反向倍率、日期输入、回到当前时间。
- 日期显示和输入明确采用 UTC，避免本地时区歧义。
- 第一版日期范围为 UTC 1800-01-01 至 2050-01-01，不包含结束时刻。
- 输入越界显示错误并保留原有效时间；运行到边界自动暂停并提示，不静默回绕。
- 切换到后台时暂停时间推进与输入，返回时继续原倍率，不补算整段后台时间。
- 相机运动使用真实帧间隔；轨道与自转使用模拟时间，禁止混用。

### 3.4 双尺度模式

默认改为真实尺度，以符合用户最终确认的漫游优先方向。

真实尺度模式：

- 天体半径与天体之间的距离使用同一物理比例。
- 屏幕大小不足以辨认的天体由可关闭的标签辅助定位，不偷偷放大实体。
- 标签拾取与天体实体拾取分离，避免使用放大碰撞球伪装真实尺寸。

示意模式：

- 仅改变显示尺寸和间距，不更改轨道计算结果和天体资料。
- 采用单一、集中定义的显示映射；行星以太阳为父级，月球以地球为父级。
- 使用保持方向、单调增加的距离映射；轨道线与天体位置必须采用相同映射。
- 各天体的显示半径与间距参数集中配置，明确标注“示意模式：尺寸与间距已调整”。
- 主要用于全景和环绕观察，不承担真实距离下的自由飞行体验。

切换模式保留模拟时间与选中天体，取消正在执行的飞向动画。相机转换为该天体的安全环绕视角；未选中天体时转换为全景，避免对非线性缩放后的任意自由相机位置作不明确的映射。

## 4. 科学模型与诚实表达

### 4.1 单位与坐标

- 模拟层：距离统一为千米，角度为弧度，时间以儒略日表示。
- 参考系：日心 J2000 黄道坐标；月球相对位置转换到同一参考系。
- 渲染坐标系与天文坐标系的轴变换集中定义并测试，不能在各天体组件中各自转换。
- 数据记录包含天体标识、父级、物理半径、轨道参数、自转参数、材质引用、来源及适用范围。

### 4.2 轨道与自转

- 实现调整：采用 Astronomy Engine 2.1.19（MIT）的天体位置模型，替代最初计划手工录入的 JPL 参数表；该表在开发环境中访问超时，不能凭记忆补造数据。仍不做逐帧多体引力积分。
- 明确区分太阳中心、地球中心与地月质心，统一转换为日心 J2000 黄道坐标；转换细节和依赖源代码证据见 `docs/data-sources.md`。
- 月球使用同一库的月球位置模型，而不是虚构圆轨道；地月相对向量与质量比例在模拟层统一处理。
- 月球模型不承诺高精度月相、摄动、交食或掩星时刻；不能把行星算法的精度说明套用到月球。
- 应用输入 UTC，时间适配与库内时间尺度的限制记录在模型说明中；本项目不定位为精密星历工具。
- 自转采用周期、方向、轴倾角和基准相位参数；正确表达逆行自转，但不承诺所有日期的表面经度精确对齐。
- 直接根据绝对模拟时间求位置与姿态，暂停、倒放和跳转不依赖累积积分。

具体来源与参数推导已记入 `docs/data-sources.md`。部分半径采用有来源的视直径系数推导近似值，不宣称所有天体均为同一精度标准。独立高精度 JPL 向量基准尚未取得，不能将现有范围/参考系测试描述为已通过该基准。

## 5. 架构与数据流

采用四个边界清晰的模块，不在首版抽象通用宇宙引擎。

| 模块 | 责任 | 不承担 |
| --- | --- | --- |
| simulation | 天体目录、时钟、轨道、自转、单位转换 | React、材质、相机操作 |
| rendering | 场景、材质、显示映射、背景、资源生命周期 | 决定模拟时间或更改物理数据 |
| navigation | 相机状态机、飞向、跟随、速度、表面限制 | 绘制资料面板、加载天文目录 |
| ui | 搜索、时间、模式、设置、信息与错误提示 | 逐帧位置计算 |

逐帧顺序：

1. 用真实帧间隔更新模拟时钟。
2. 根据当前模拟时间计算天体物理状态。
3. 根据输入、目标和物理状态更新相机。
4. 应用尺度映射与相机相对坐标转换。
5. 渲染场景，低频刷新 HUD。

React 负责结构和低频交互状态；逐帧姿态和位置保存在模拟与相机运行时对象中，不为每个天体逐帧触发 React 状态更新。

预计代码放在 `src/simulation`、`src/rendering`、`src/navigation`、`src/ui`；具体文件和依赖版本在实施计划中明确，不在本阶段创建空目录骨架。

## 6. 大尺度渲染策略

- 模拟层和相机位置使用 JavaScript 数值保存物理坐标。
- 传入 GPU 之前减去相机位置，再换算为渲染单位；不能先转成低精度绝对坐标再相减。
- 星空使用独立背景，不跟随相机平移，也不把巨大背景球和近景共用一个深度范围。
- 优先验证相机相对原点、动态裁切范围和独立背景。
- 如果原型仍存在不可接受的深度问题，在进入视觉阶段前决定分层渲染等补充策略；不能用放大真实模式中的行星绕过问题。
- 天体实体、轨道线、标签必须在同一帧使用一致的原点与显示映射。

原型必须覆盖地球近景、月球附近、土星环和海王星远景；有限太阳系范围不按无限宇宙设计。

## 7. 视觉、资源与错误处理

- 第一版先使用标准光照和可维护的小型效果，再考虑自定义复杂着色器。
- 太阳可见表面和照亮天体的光源分离；光晕不是实际光源。
- 地球的大气、云层、夜景是可独立降低质量的效果。
- 优先加载低分辨率基础材质；飞近天体时请求高一级纹理。
- 高频切换目标时去重请求，限制同时加载数量并释放不再缓存的纹理。
- 高分辨率素材不依赖第三方临时 URL；批准后将许可允许的资源纳入项目静态资产或受控发布目录。
- 每个资产记录作者、原始来源、许可、修改情况与署名要求，发布时生成或维护鸣谢清单。
- 未确认使用与再分发许可的素材不纳入发布。
- 加载中与加载失败状态可区分；失败显示具体天体及重试入口。
- WebGL 初始化失败显示不支持提示；上下文丢失时显示恢复状态，恢复失败提供重新加载入口。
- 暂时使用占位材质时显式标记，不能把无纹理场景当作完成态。

## 8. 性能目标

目标设备以用户提供的信息为准，最终性能需在该设备上测量。

- 标准档验收内部渲染分辨率为 1920 × 1080；高 DPI 或 4K 显示器不自动强制同等渲染分辨率。
- 常规热缓存漫游争取 60 FPS；使用帧时间而不只看瞬时 FPS。
- 每个代表场景预热 10 秒、记录 60 秒；目标中位帧时间不高于 16.7 ms，P95 不高于 22 ms，排除冷加载但单独记录冷加载停顿。
- 代表场景包括地球云层近景、土星环近景、太阳系全景，以及地球到海王星的导航。
- 重复往返导航后资源计数与缓存估算应趋于稳定；不能随访问次数持续增长。
- 纹理初始缓存预算为估算解码后 256 MiB，包含各 mip 层；这不是整个浏览器进程的内存承诺。
- 至少提供标准和低画质档；高档在标准档达标后再确定，不以关闭核心导航功能达标。
- 若原型不达标，先定位问题，再削减效果或调整渲染方案，明确记录偏差。

## 9. 分阶段交付与退出条件

### A：尺度与导航原型

用简单球体完成十个核心天体、真实/示意映射和相机状态机。

退出条件：

- 能从地球近景飞向海王星、返回地球、观察月球和土星环所在区域。
- 飞向可中断，跟随不随天体自转甩动相机。
- 相机不进入核心天体内部，飞向路径不穿越天体。
- 切换模式保持时间和选中目标，转换后的视角有效。
- 在标准分辨率下无明显近景抖动、物体裁切和无法恢复的目标丢失。

### B：太阳系核心

接入有来源的数据、时间、搜索、天体选择、轨道、标签与资料。

退出条件：

- 十个核心天体都可搜索、选中、飞近和跟随。
- 暂停、正反倍率和跳转时间工作一致，边界行为符合第 3.3 节。
- 地月质心与地月相对坐标关系正确，模拟层不依赖渲染组件。
- 输入搜索和日期时不触发飞行控制。

### C：视觉成品

接入授权素材、光照、土星环、地球大气/云层/夜景、太阳光晕和简洁界面。

退出条件：

- 地球、土星和太阳三个重点视角满足用户确认的视觉方向。
- 光照方向随实际位置变化，夜景主要显示在背光侧。
- 完成第 8 节的性能记录，并明确没有达到的目标。
- 在进入具体界面样式实现前，确认布局和视觉参考；不默认像素级复刻参考软件。

### D：发布与完善

完成画质设置、错误处理、帮助、鸣谢、本地运行说明和静态部署。

退出条件：

- 本地开发和生产构建可用；支持静态站点子路径，不把资源路径硬编码为域名根路径。
- 刷新、调整窗口、后台恢复、失败重试和上下文恢复行为明确。
- 部署后的资源来源与许可清单完整，无专有软件提取资产。

## 10. 验证策略

- 单元验证：单位与坐标转换、开普勒求解残差、日期边界、轨道样例、地月质心、显示映射单调性、相机安全距离、状态切换。
- 对多个日期与天体检查独立的距离范围与参考系约束；外部高精度星历基准另行标记未覆盖，不用实现本身生成预期值冒充独立基准。
- 集成验证：暂停/倒放/跳转后的跟随、飞向取消、模式切换、输入焦点与失焦。
- 浏览器流程验证：启动、搜索、飞向、时间控制、模式切换、窗口变化、资源失败。
- 视觉验证：固定模拟时间、随机种子、视角和渲染分辨率；稳定场景截图与人工观感检查结合。
- 性能验证：独立执行第 8 节的场景；无头浏览器结果不能替代目标机器上的实际 Chrome 测量。
